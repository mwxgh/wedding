# Project guide for AI agents

Read `README.md` first (how to run, repo layout, conventions).

Rules:

- Conventional Commits: `type(scope): subject` (scopes in `commitlint.config.mjs`).
- Before finishing: `pnpm turbo run build lint check-types test`; schema change → `pnpm db:push` (no migration files while in development) and commit `packages/types/src/generated`.
- Shared Nest infra goes to packages (`@repo/db/nest`, `@repo/nest-common`), not into the app. Feature code stays in `apps/api/src/<feature>`.
- Prisma-generated types are the single source for model shapes: web imports models and enums from `@repo/types` (generated by `pnpm db:types`, committed; never edit or redeclare model fields). Response types for the web live in `packages/types/src/responses.ts`; the API's Prisma query shapes live in `apps/api/src/common/responses.ts` with compile-time drift checks.
- `api` only uses `import type` from `@repo/types`; runtime enums in the API come from `@repo/db`. Pure helpers shared by api and web go to `@repo/utils`.
- Request DTOs are classes using the field decorators from `@repo/nest-common`, implementing the request interface from `@repo/types`.
- Dependency versions: shared ones live in the `catalog:` of `pnpm-workspace.yaml`, referenced as `"catalog:"`; a package that must share the app's instance (class-validator, Nest, React) declares it in `peerDependencies`.
- UI: shadcn components live in `packages/ui` (add with `pnpm dlx shadcn add <name> --cwd packages/ui`).

# This is NOT the Turborepo you know

Turborepo configuration, task behavior, and CLI commands can vary between installed versions and may differ from your training data. Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. For example, run `node -p "require.resolve('turbo/package.json')"` from a workspace that depends on `turbo`.

Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

This block is written and re-added by `turbo` before repository-scoped commands when an AI agent is detected. In the Turborepo source repository, its template is defined in `crates/turborepo-cli/src/cli/agent_guidance.rs`. Removing the managed block while updates are enabled means a later qualifying invocation will add it again. Set `"agentGuidance": false` in the root `turbo.json` or `turbo.jsonc` to opt out; this does not remove an existing block. Keep the block committed with your work to avoid an uncommitted change on the next agent invocation.
